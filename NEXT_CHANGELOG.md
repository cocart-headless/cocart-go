# Next Changelog for CoCart Go SDK <!-- omit in toc -->

> [!WARNING]
> This changelog is **NOT** final. It lists the changes waiting for the next release of `github.com/cocart-headless/cocart-sdk-go`, to be moved into a changelog under the new version when it's released.

## Changed

- **Retries never send a change twice.** With `WithMaxRetries` set, a request that changes something (a POST, PUT or DELETE: placing an order, paying, adding to the cart) is no longer sent again after a timeout or a dropped connection, as it may already have run on the store: a retried checkout could charge the card twice. A 429 is still retried for any request, since the rate limit refuses it before it runs, and a 503 or timeout for a GET.
- **The response types now match what CoCart sends.** The structs for carts, products, variations, the store and sessions were written by hand and didn't match the API, so `Unmarshal[CartResponse]` and `Unmarshal[Product]` returned an error on a real store and fields such as the cart's shipping, fees and notices, image sources and product attributes came back empty. They now follow the CoCart spec and are checked against recorded responses. Code using the old fields needs updating:
  - Cart: `Shipping` is a `CartShipping` (packages keyed by package ID), `Fees` an `ObjectMap[CartFee]`, `Notices` an `ObjectMap[[]string]` keyed by type, `Taxes` a `CartTaxes` list, `RemovedItems` a `[]RemovedItem`, and `ItemsWeight` and `CartItemMeta.Weight` are `FlexString` (CoCart sends strings). The customer's addresses are `CartBillingAddress` and `CartShippingAddress`, matching CoCart's prefixed fields (`billing_email`…); `CustomerAddress` is deprecated. `ShippingRate.Tax` is now `Taxes`, and `CrossSellProduct` has `ProductName`, `ProductTitle` and `ProductImage` in place of `Name`, `Slug` and `FeaturedImage`.
  - Products: `ProductImage.Src` maps size names to URLs (`Thumbnail` is gone), `Product.Attributes` is keyed by attribute (`ObjectMap[ProductAttributeDetail]`), `ProductVariation.Attributes` is an `ObjectMap[ProductVariationAttribute]`, and `Product.Conditions` is gone (use `AddToCart.IsPurchasable` and `HiddenConditions`).
  - `StoreInfo` has `Title`, `Description` and `HomeURL` in place of `StoreName`, `StoreDescription` and `StoreURL`, and `SessionItem` has the fields of the sessions list (`CartKey`, `CustomersName`, `CartExpiry`…).
  - Maps are `ObjectMap` values, which accept both the `{}` CoCart Starter 5 sends for an empty map and the `[]` CoCart 4.x sent.
- **`Response.GetNotices()` returns notices keyed by type** (`map[string][]string{"success": …, "error": …}`), which is how CoCart sends them, instead of a `[]any`. When there are none it returns an empty map.
- **`NewClient` remembers the cart on its own.** It now reads the cart key from its storage adapter when it's created, unless `WithCartKey` gives one. Before, a storage that outlived the process started a new cart unless you called `RestoreSession()`. `FromRequest` still takes the cart key from the request only, since a server may share one storage between customers.
- **A guest cart that no longer exists is replaced automatically.** CoCart Starter 5 refuses a cart key with no cart session on every cart route (`cocart_invalid_cart`), for example after the cart expired. The client then forgets the stored cart key and retries the request once as a new guest, so the shopper isn't stuck.
- **`OrderByPrice` is gone**, because CoCart rejects `"price"`: sort by price with `OrderByPriceAsc` or `OrderByPriceDesc`.
- Connection errors from `RequestRaw` (the account routes and `Batch`) were returned as `net/http`'s `*url.Error`; they're now a `*CoCartError` with the `network_error` code, like other requests.
- **`MainPluginBasic` (`"basic"`) is renamed `MainPluginStarter` (`"starter"`)**, after the CoCart Starter plugin. It's the default and what `GetMainPlugin()` returns. `RequiresBasic()` is renamed `RequiresStarter()`.
- **A 409, 429 or 5xx is never a `*ValidationError`.** It was when its code contained `invalid` or `missing` (`cocart_order_invalid_status` is a 409); it's now a plain `*CoCartError`. A 400 is still a `*ValidationError` and a 401 or 403 an `*AuthenticationError`.
- **`RequestRaw`, which every CoCart Plus route uses, now emits `OnRequest`, `OnResponse` and `OnError` events and shows in the debug output**, like the other requests, and its error messages name the route (`POST /cocart/v2/checkout: … [code]`). It still never sends a request again.

## Added

- `Response.GetShipping()` returns the cart's whole `shipping` field: the package count, whether shipping has been calculated, and the packages.
- `Response.GetExtensions()` reads the cart's `extensions`, and `Response.GetRateLimit()` the `RateLimit-*` headers (`RateLimitInfo`).
- Methods for the CoCart Plus 2.0 routes the SDK didn't cover: `Cart().GetMini()`, `Cart().RemoveCoupons()`, `Cart().RemoveAllItems()` (keeps coupons and fees), `Products().ShippingRates()`, `Products().CreateReview()`, and on `Account()`: `Register()`, `UpdateAddress()`, `CancelOrder()`, `VerifyEmail()`, `SendOrderEmailVerification()`, `VerifyOrderEmail()`, the subscription methods (`GetSubscriptions()`, `GetSubscription()`, `SuspendSubscription()`, `ReactivateSubscription()`, `CancelSubscription()`, `SetSubscriptionAutoRenew()`, `UpdateSubscriptionPaymentMethod()`, `Resubscribe()`, `CancelResubscribe()`) and `RequestOrderWithdrawal()`. `GetOrders()` filters by `status` (several comma-joined: `"processing,on-hold"`), by date with `after` and `before`, and by `subscription_order_type`, and `GetSubscriptions()` by `status`; both take `formatted` (`"true"`) and `meta_keys` (comma-joined), as do `GetProfile()`, `GetOrder()` and `GetGuestOrder()` (an optional `map[string]string`).
- `ApplyCoupon()` and `CheckCoupons()` take an optional email for coupons restricted to certain emails; `AddFee()` takes an optional tax class.
- `CoCartError.GetCart()` returns the cart sent with an error: `cocart_item_not_in_cart` carries the current cart since CoCart Starter 5.
- `CoCartError.Fields()` gives every field at fault, by path (`billing.postcode`), with its message: CoCart Plus checks a whole form at once. It's an empty map when the error isn't about fields. `Field()` gives the first field at fault, and `Reason()` the underlying plugin's own reason (`""` when there is none).
- `ResponseEvent.Response` carries the response received.
- **Choices for CoCart Plus's supported plugins.** `AddItem()`'s options are documented for a subscription plan (`convert_to_sub`), a gift recipient (`recipient_email`) and a warranty (`item_data` `warranty`); other plugins' fields still pass through. `Cart().ChangePlan(ctx, itemKey, value)` switches a cart item to another plan, or to one-time with `"0"`.
- New types: `CartTotalsBreakdown` (the `GET /cart/totals` breakdown), `CartBillingAddress`, `CartShippingAddress`, `CartShipping`, `RemovedItem`, `ProductsResponse`, `ProductAttributeDetail`, `ProductVariationSummary`, `ProductCategoryDetail`, `ProductBrand`, `ConnectedProduct` and the other parts of a product, `ProductReviewInput`, `ProductShippingRatesParams`, `RegisterCustomerInput`, `RateLimitInfo`, and `ObjectMap` and `FlexString` for the values CoCart sends in more than one shape.
- The sort orders CoCart accepts: `OrderByMenuOrder`, `OrderByName`, `OrderByAlphabetical`, `OrderByReverseAlpha`, `OrderBySales`, `OrderByReviewCount`, `OrderByStock`, `OrderByOnSaleFirst`, `OrderByFeaturedFirst`, `OrderByPriceAsc`, `OrderByPriceDesc`, and with CoCart Starter `OrderByRelevance` and `OrderByRand`.
- `docs/account.md` covers the Account API, and `docs/extension-data.md` lists the data CoCart Plus adds under `extensions` for the plugins it supports, and how to send the customer's choices.
- **Checkout (CoCart Plus 2.0).** `client.Checkout()` places orders and takes payment: `PlaceOrder()` with `payment_data` as a map of the keys the gateway reads (`{"wc-stripe-payment-method": "pm_…"}`), and a free order needs neither `payment_data` nor `payment_method`. It returns a `*CheckoutResult`, read from the order CoCart Plus 2.0 returns with what the payment did in `result`: `Code` (a `PaymentResultCode`: `PaymentOrderPlaced`, `PaymentActionRequired`, `PaymentPending`, `PaymentFailed`, or `PaymentMethodChanged` for a subscription), `IsComplete()`, `IsAwaitingPayment()` (the order is placed and the customer still pays: Cash App Pay, WeChat Pay, Stripe vouchers, BLIK, a Multibanco voucher), `NeedsConfirmation()` for 3D Secure, `NeedsRedirect()` for an off-site step, `IsPending()`, `IsFailed()`, `Object`, the order's `OrderID`, `OrderKey`, `OrderNumber` and `OrderStatus` (or `SubscriptionID`), `RedirectURL`, `ClientSecret`, `PaymentMethodType`, `Message`, `ErrorCode`, `ActionType` and `ActionData`, so a declined card is a result to read, not an error. Printing a result (`%v`, `%+v`, `%#v`) never shows `ClientSecret` or `OrderKey`. `PayForOrder()` (including 3D Secure), `ConfirmReturn()` and `ConfirmReturnFor()` return the same result; `PayForOrder()` and `ConfirmOrderPayment()` send the order key in the body, not the URL. Also `Get()` (optionally with `currency`, `formatted` and `thumb`), `Update()` (which says what it did in `result`: `checkout_updated`, or `checkout_partly_updated` with `result.not_applied`), `Process()`, `GetConfig()`, `GetPaymentMethods()` (the list of methods itself; read it with `Unmarshal[[]map[string]any]`), `GetSavedPaymentMethods()` (typed `SavedPaymentMethod`: `ID`, `GatewayID`, `Label` such as "Visa ending in 4242", `Type`, `Expires`, `IsDefault`, and `SupportsSubscriptions`), `SearchAddresses()`, `GetAddressDetails()`, `GetOrderReceived()` (optionally with `formatted` and `meta_keys`) and `ConfirmOrderPayment()`. The checkout is tested on the request and response data every CoCart SDK replays (`testdata/checkout`). See `docs/checkout.md`.
- **Checkout: finding out how an order ended when no answer came back.** `PlaceOrder()` sends each order with a random `checkout_id` (or yours, in the input: 16 to 64 letters, digits, `-` or `_`, or it's refused before sending with `checkout_invalid_checkout_id`). When the connection drops, the request times out, a proxy gives up waiting, or another request is still taking payment for the cart (`409 cocart_payment_in_progress`), it returns a `*CheckoutOutcomeUnknownError` (wrapping the `*CoCartError`) with `CheckoutID`, and `Checkout().GetStatus(ctx, checkoutID)` asks CoCart Plus 2.0 how it ended (`*CheckoutStatus`): its `Code` is `order_placed`, `payment_required` (pay it with `PayForOrder()`), `in_progress` (ask again) or `not_placed` (place it again), with a `Message` and, once there is an order, `OrderID`, `OrderKey`, `OrderNumber` and `OrderStatus`.
- `Account().UpdateSubscriptionPaymentMethod()` takes a new card in `payment_data` as well as a saved card's `token_id`, and returns a `*CheckoutResult` read from the subscription it returns, since a new card may need 3D Secure: `IsComplete()` once the change went through (`PaymentMethodChanged`, with `SubscriptionID`).

## Fixed

- **`WithHTTPClient` had no effect.** `NewClient` replaced the client it was given with its own, so a custom transport, proxy or TLS setting was ignored. The client passed in is now used.
- **`Response.GetShippingMethods()` always returned an empty list on a real store.** CoCart sends shipping packages keyed by package ID under `shipping.packages`; `GetShippingMethods()` now returns them as a list, in the order CoCart sent them.
- **`Response.GetFees()` always returned an empty list on a real store.** The cart keys fees by fee ID; `GetFees()` now lists them.
- **`ApplyCoupon()` was rejected by CoCart Plus** because it sent the code as `coupon` instead of `code`.
- **`AddFee()` was rejected by CoCart Plus** because it sent the amount as a number; the route takes a string.
- **`Account().ChangePassword()` and `GetReviews()` called routes CoCart Plus doesn't have.** The password now goes to `POST /my-account` (only the password fields), and reviews come from `products/reviews/mine`.
- **`WithDebug` logged nothing.** It now logs each request, response, error and retry with the standard `log` package, with every query value in a URL shown as `***`, so the cart key, an order key, a guest's email or an email verification key don't reach the logs. Event listeners still get the full URL: don't forward it as it is.
- **With `WithMaxRetries`, a rate-limited request was retried too soon.** CoCart Plus says how long to wait in `RateLimit-Retry-After`, which the client didn't read, so it retried after a second or two and hit the limit again. It now waits as long as the store says (at most 60 seconds), and still reads `Retry-After` from a proxy.
- **The ETag cache kept responses the store marks private.** Checkout, order and account responses are sent with `Cache-Control: no-store, private`; the client no longer keeps them in memory.
- **`RemoveCoupon()` broke for coupon codes with spaces, `%`, `#` or `?`.** The code went into the URL unencoded. It's now encoded.
- **Error messages included the full request URL**, which can contain the cart key and API credentials. They now name only the route, e.g. `POST /cocart/v2/cart/add-item: Product not found. [cocart_product_not_found]`.
- **Connection error messages included the cart key.** `net/http` puts the request URL, query string included, in its errors, and the SDK passed that message on (or returned the error as it was from `RequestRaw`). The query string is now removed, and the original error is no longer returned.
- `docs/store.md` read the store's name, description and URL from fields CoCart doesn't send, and the docs read product prices from `price`. They're `title`, `description` and `home_url`, and prices are under `prices` (minor-unit strings).
